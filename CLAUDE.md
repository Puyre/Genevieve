## Практические заметки для Claude

### Команды сборки и запуска
- `./gradlew build` — полная сборка
- `./gradlew test` — запуск тестов (JUnit Platform; каталог `src/test/kotlin/` пока пуст)
- `./gradlew run` — запуск `Main.kt` (откроется AWT-окно с визуализацией)
- `./gradlew -q compileKotlin` — быстрая проверка компиляции, используется для верификации правок
- `./gradlew ktlintCheck` / `./gradlew ktlintFormat` — линтер (Kotlin official style)
- Требования: Kotlin 2.2.21, JVM toolchain 17

### Ограничения и гочи
- **Skiko привязан к macOS ARM64.** Зависимость `skiko-awt-runtime-macos-arm64` в `build.gradle.kts` жёстко задана. На Linux/Windows проект без замены рантайма не соберётся.
- **`ImageEncoderConfig` JSON — load-bearing.** Персистентный конфиг детекторных кластеров (таблица код → `EdgePrototype`) должен быть стабильным между запусками. Перегенерация инвалидирует ранее закодированные векторы: один и тот же бинарный код может начать соответствовать другому прототипу границы.
- **MNIST изображения** лежат в `src/main/resources/mnist/` (28×28 grayscale PNG).

### Язык новых материалов
Новая проза (CLAUDE.md, документация, docstrings) и комментарии в коде — на русском. Идентификаторы и commit-сообщения остаются на английском, как в текущей истории репозитория.

## Фундаментальная гипотеза

### Почему LLM - это не мышление

Современные языковые модели (LLM) работают по принципу статистического анализа текста. Они предсказывают следующий токен на основе паттернов, встреченных в обучающих данных. Это sophisticated pattern matching, но не reasoning в человеческом смысле.

Ключевые ограничения LLM:
- **Нет понимания** - модель не знает, что такое "яблоко", она знает только, какие слова обычно стоят рядом со словом "яблоко"
- **Нет мировой модели** - отсутствует внутреннее представление о том, как устроен мир
- **Комбинаторный взрыв** - для каждой новой ситуации нужны новые примеры в обучении
- **Хрупкость** - небольшие изменения в формулировке могут радикально изменить ответ

### Контекстно-семантическая модель мозга

Проект основан на модели Алексея Редозубова. Центральная идея:

**Контексты - это не детекторы признаков, а правила геометрической трансформации.**

Классический подход (CNN, детекторы Хаара и т.д.): система ищет конкретные паттерны в данных. "Есть ли здесь вертикальная линия? А горизонтальная? А глаз?"

Наш подход: система применяет трансформации к данным, пока не найдёт совпадение с шаблоном. Контекст "сдвиг влево на 2 пикселя" - это не детектор, это операция. Один и тот же контекст работает для любых объектов в одинаковой пространственной конфигурации.

**Почему это решает комбинаторный взрыв:**
- Классический подход: нужен отдельный шаблон для "яблоко слева", "яблоко справа", "яблоко сверху"...
- Контекстный подход: один шаблон "яблоко" + контексты трансформаций (сдвиг, поворот, масштаб)

### Архитектура мышления

Гипотеза о том, как работает мышление (на основе нейробиологии таламо-кортикальных петель):

1. Кора применяет контексты к входным данным
2. Результат отправляется в таламус для координации
3. Таламус возвращает модулированный сигнал для дальнейшей обработки
4. Цикл повторяется, пока не найдётся совпадение с шаблоном

В искусственной реализации мы можем применять все контексты параллельно - это преимущество над биологическими ограничениями.

### Что мы НЕ пытаемся решить

Сознание. Это философски неразрешимая проблема (hard problem of consciousness по Чалмерсу). Мы фокусируемся на механизме мышления, а не на субъективном опыте.

## Визуальный модуль - детальное описание

### Цель модуля

Преобразовать изображение в sparse binary vector, который сохраняет структурную информацию о границах и их ориентации. Это первый этап перцепции - создание представления, с которым потом будут работать контекстные трансформации.

### Архитектура

#### Уровень 1: Детекторы (Detector)

Детектор - это маска NxN (сейчас 3x3), которая применяется к участку изображения и возвращает числовое значение активации.

Каждый детектор чувствителен к определённому типу границы:
- Направление границы (0°, 45°, 90°, 135° и их инверсии)
- Полярность (где светлее - сверху или снизу, слева или справа)

Маска содержит веса: -1 (ожидаем тёмное), 0 (игнорируем), +1 (ожидаем светлое).

Применение маски: поэлементное умножение с пикселями изображения, затем сумма. Высокое положительное значение = граница найдена.

#### Уровень 2: Кластер детекторов (DetectorCluster)

Кластер - это набор детекторов, применяемых к одной и той же позиции изображения. Каждый кластер "смотрит" на область изображения и выдаёт бинарный вектор.

Текущая конфигурация: 8 детекторов на кластер (направления 0°, 45°, 90°, 135°, 180°, 225°, 270°, 315°).

Выход кластера: IntArray из 0 и 1, где 1 означает "детектор активировался" (превысил порог активации).

#### Уровень 3: Энкодер изображения (ImageEncoder)

Энкодер размещает сетку кластеров по изображению с определённым шагом (stride).

Параметры:
- `maskRadius` - радиус маски детектора (1 = маска 3x3)
- `detectorActivationThreshold` - порог для бинаризации выхода детектора
- `stride` - шаг между центрами соседних кластеров

Выход: один длинный IntArray - конкатенация выходов всех кластеров.

#### Прототипы границ (EdgePrototype)

Enum, описывающий все известные типы границ:
- `HORIZONTAL_DARK_TOP` - горизонтальная граница, сверху темнее
- `HORIZONTAL_DARK_BOTTOM` - горизонтальная граница, снизу темнее
- `VERTICAL_DARK_LEFT` - вертикальная граница, слева темнее
- `VERTICAL_DARK_RIGHT` - вертикальная граница, справа темнее
- Аналогично для диагоналей 45° и 135°
- `EMPTY` - однородная тёмная область

Каждый прототип содержит эталонную матрицу 3x3, которая прогоняется через кластер при инициализации. Результат записывается в конфиг: код кластера → тип границы.

#### Конфигурация (ImageEncoderConfig)

Сериализуется в JSON для сохранения между сессиями:
- `clusterCodeDimension` - размерность выхода кластера (8)
- `maskRadius` - радиус маски (1)
- `stride` - шаг сетки кластеров
- `codeToEdgeType` - Map<String, EdgePrototype>, связывает бинарный код с типом границы

Это критически важно: без сохранения конфига каждый запуск может дать разную кодировку для одних и тех же границ.

### Визуализация

Графическая визуализация (Java AWT) отображает результат кодирования:
- Каждая ячейка соответствует одному кластеру
- Ячейка рисуется в соответствии с EdgePrototype (горизонтальная линия, вертикальная, диагональ)
- Цвет показывает полярность границы (где темнее, где светлее)
- Серая ячейка = код не найден в конфиге (неизвестная граница)

### Логика работы модуля

1. **Инициализация:**
    - ImageEncoder создаёт маски детекторов
    - Прогоняет эталонные паттерны (EdgePrototype.data) через кластер
    - Записывает соответствие код → прототип в конфиг
    - Сохраняет конфиг в JSON

2. **Кодирование изображения:**
    - Загрузка PNG, бинаризация пикселей (порог) в -1/+1
    - Размещение сетки кластеров по изображению
    - Каждый кластер применяет все детекторы к своей области
    - Бинаризация выходов детекторов (порог активации)
    - Конкатенация всех кодов в один вектор

3. **Визуализация:**
    - Разбиение вектора обратно на коды кластеров
    - Поиск каждого кода в конфиге
    - Отрисовка соответствующего паттерна в ячейке

## Текущее состояние

Реализован базовый pipeline: загрузка PNG → кодирование → визуализация. Тест на синтетическом круге работает хорошо. Тест на MNIST даёт узнаваемый, но неполный результат - много "серых" ячеек (неизвестных кодов).

## Направление развития

Цель ближайшего этапа: добиться, чтобы визуализация закодированного изображения была визуально похожа на исходное изображение. Это докажет, что модуль перцепции корректно захватывает структурную информацию.
